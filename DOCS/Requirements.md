# Функциональные и нефункциональные требования: DataBridge

## 1. Введение и назначение
DataBridge — консольная утилита обработки табличных данных, предназначенная для чтения данных из разнородных источников, их проверки по гибко настраиваемым бизнес-правилам, выполнения трансформаций и конвертации в целевой формат с формированием детализированных отчётов.

Проект не является учётной системой или СУБД; его назначение — автономный потоковый конвейер ETL (Extract, Transform, Load) на уровне файлов.

---

## 2. Функциональные требования

### 2.1. Чтение входных данных (Extract)
1. **Поддерживаемые форматы**:
   - **CSV**: поддержка произвольных разделителей (запятая, точка с запятой, табуляция), заголовков (наличие/отсутствие), различных кодировок (UTF-8, UTF-8 with BOM, CP1251).
   - **JSON**: массив плоских объектов (`[{"key": "value"}, ...]`).
   - **XML**: плоские древовидные структуры (`<data><row>...</row></data>`).
   - **Excel**: форматы `.xlsx` (OpenXML) и `.xls` (устаревший двоичный BIFF8).
   - **Parquet**: чтение промежуточных бинарных колоночных срезов.
2. **Автоматическое определение формата**:
   - Определение формата файла по его расширению (`.csv`, `.json`, `.xml`, `.xlsx`, `.xls`, `.parquet`).
   - Возможность явного указания формата при необходимости.

### 2.2. Валидация данных (Validate)
Валидация выполняется построчно на основе декларативной схемы (в формате JSON или YAML).

1. **Типы валидационных проверок**:
   - `required`: проверка на обязательное заполнение поля (значение не null, не NaN и не пустая строка/пробелы).
   - `type`: проверка соответствия типа данных:
     - `integer`: целое число;
     - `float`: вещественное число (с поддержкой точки и запятой в качестве разделителя);
     - `string`: строковое значение;
     - `boolean`: булево значение (True/False, 1/0, "true"/"false", "yes"/"no", "да"/"нет");
     - `date`: дата заданного формата (по умолчанию `YYYY-MM-DD`).
   - `unique`: контроль уникальности значений в столбце по всему датасету.
   - `min` / `max`: диапазон допустимых значений (для числовых полей и дат).
   - `pattern`: валидация по регулярному выражению (RegEx) для строк (например, email, телефон, СНИЛС).
   - `min_length` / `max_length`: ограничение длины строки (минимальное и максимальное количество символов).
2. **Маршрутизация некорректных записей**:
   - Невалидные записи исключаются из основного потока конвертации.
   - Ошибочные строки сохраняются в отдельный файл `errors.csv` с сохранением исходной структуры данных для последующего исправления пользователем.

### 2.3. Трансформация и маппинг данных (Transform)
1. **Маппинг колонок**:
   - Переименование полей по правилу `target_name` из конфигурации схемы.
2. **Встроенные трансформации**:
   - `trim` / `strip`: удаление начальных и завершающих пробелов;
   - `uppercase` / `lowercase`: приведение регистра символов;
   - `timestamp_to_date`: преобразование Unix-timestamp (в секундах или миллисекундах) в дату формата `YYYY-MM-DD`;
   - `replace` / `dictionary`: замена кодов и аббревиатур по словарю соответствия.
3. **Промежуточное хранение**:
   - Автоматическое сохранение очищенного промежуточного состояния в бинарный формат Parquet для повышения отказоустойчивости и оптимизации пайплайна.

### 2.4. Запись выходных данных (Load)
1. Поддержка выгрузки в форматы: `csv`, `json`, `xml`, `xlsx`, `parquet`.
2. Сохранение валидных строк в результирующий файл, указанный пользователем.

### 2.5. Отчётность (Reporting)
1. **Консольная сводка**:
   - Вывод общего числа записей, количества успешно обработанных и количества ошибок.
   - Детализация ошибок с указанием номера строки, имени поля и причины отклонения.
   - Пути к результирующим файлам (`output`, `errors.csv`, `report.html`).
2. **HTML-отчёт**:
   - Автономный HTML-документ с визуальными карточками метрик, индикатором статуса и таблицей дефектов.
3. **Профилирование данных (`stats`)**:
   - Вывод сводной таблицы: типы колонок, заполненность, доля пропусков, количество уникальных значений, числовые параметры (min, max, avg).

## 3. Нефункциональные требования

1. **Язык и окружение**: Python 3.10+ с использованием библиотек `pandas`, `pyarrow`, `openpyxl`, `xlrd`, `lxml`, `pyyaml`.
2. **Отсутствие внешних СУБД**: архитектура работает исключительно с файловой системой.
3. **Надёжность и обработка исключений**:
   - Приложение перехватывает ошибки ввода-вывода (IOError, FileNotFoundError, PermissionError) и невалидные структуры.
   - Ошибки выводятся в понятном пользователю виде без вывода необработанных stack trace.
4. **Тестируемость**:
   - Модульное тестирование (минимум 15 unit-тестов, покрывающих чтение, валидацию, трансформации, CLI и граничные случаи).
5. **Архитектура**:
   - Чёткое разделение ответственности по пакетам (`readers`, `validators`, `converters`, `reporters`, `cli`).
   - Принципы SOLID и модульный дизайн.
